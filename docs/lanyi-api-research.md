## 实测接入与交付

1. 兑换码用于把额度记入账户。随后在令牌管理生成 API Key，供客户端或 GitHub Actions 使用。把兑换码当 Key 时云端得到 401。
2. Anthropic Messages 的 Base URL 用根域名，请求路径是 /v1/messages。初始 claude_code 分组对 claude-fable-5 返回 503 model_not_found。切到官转max（当时 2.5 倍）后，claude-fable-5、claude-fable-5-1、claude-fable-5-2 均返回 HTTP 200 与有效文本。分组、价格和可用性以实测时点为准。
3. 教程交付可追踪已兑换、已生成令牌和首次调用成功三个节点。实操曾在本机密码自动填充处要求本人验证。客服可按卡点给出下一步。

## 商业模式与上限

兑换码让首单能重复交付。按工具拆分的教程减少配置失败，也可能承接有明确接入需求的搜索流量。企业微信承担售后与复购，赠额绑定下一次充值。按模型、分组和实际调用消耗余额，是持续收入的来源。教程还出现了把模型包装成直接可用工具的尝试。

经营账分别看充值现金、实际消耗对应的收入、未用余额和利润。贡献需扣上游、支付、退款补偿及按量费用，再算客服、获客和固定开支。若有 2,000 名月付费活跃用户、人均实际消费 100 元、按量成本后贡献率 20%，则月实际消费对应收入 20 万元，贡献 4 万元。这是情景算术。蓝移真实营收、采购、毛利、复购和授权情况未知。上限取决于稳定上游、复购、客服时间与可归因获客。

个人验证可先针对一个工具和一类客户，交付可验收的接入或工作流，记录咨询、付费、首次调用、返工和后续付费。客户可直接支付自己的模型用量，服务费覆盖配置与排错。自营网关需要单独验证上游授权、真实成本和故障支持。

## Static IP Playbook

该仓库是网络操作手册。要点是区分自有 VPS 的入口与有要求时才采用的固定出口，核对代理分流、DNS、IPv4/IPv6、证书、实际客户端连通和重连稳定性。可以把它用作 API 排障清单。HTTP 401 查凭据，503 model_not_found 查分组与路由，固定 IP 不替代这两项验证。采购链接、价格和固定版本需回源核实。LearnAI 的教程应使用各用户自己在平台生成的 Key，Claude 文章在平台中转上线前标明状态。

## 复盘与验证指标

| 环节 | 建议观察的指标 | 可定位的问题 |
| --- | --- | --- |
| 从商品到文档 | 进入教程率、首次咨询耗时 | 商品说明、渠道承诺和交付步骤是否一致 |
| 从文档到兑换 | 兑换成功率、余额到账异常 | 登录接手、码有效期、账户与站点是否匹配 |
| 从兑换到调用 | 创建令牌率、首次成功耗时、按状态码归类的错误 | 凭据误填、Base URL、模型 ID、分组路由 |
| 从使用到复充 | 7/30 天消耗与复充率、每百用户工单量、赠额实际消耗 | 客户是否持续使用，赠额是否带来增量复购 |
| 供给与利润 | 按模型和分组的实际账单、失败率、支付与补偿、每单客服时间 | 哪些分组能支撑扩量，故障如何影响毛利 |

规模测算可用“月付费活跃 × 人均实际消耗 × 扣除上游和按量费用后的贡献率”。例如 300 人 × 60 元 × 15% 对应每月 2,700 元贡献，2,000 人 × 100 元 × 20% 对应 4 万元，10,000 人 × 150 元 × 25% 对应 37.5 万元。以上是测试经营假设的三组算术，人工和固定成本另计。真实规模要用经营数据验证。

个人可先花两周验证一个小商品，例如协助独立开发者接通一个指定工具、完成一个真实任务并交付排错步骤。用可验收的固定服务费，记录每单耗时和实际续费原因，再决定把常见问题做成自助教程、维护包或专用工具。若客户持续为统一账单、多模型路由和故障切换付费，再核实网关的上游授权、调用成本和售后能力。

## 证据边界

普通账户侧导航已逐项盘点。测试覆盖兑换到账、令牌配置、Anthropic Messages 和失败排查。在线支付、退款、邀请奖励兑现、异步任务实际产出、管理员功能、供应商合同和经营数据需要另取证。
